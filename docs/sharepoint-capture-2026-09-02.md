# SharePoint Word-open capture, 2026-09-02

Source: a private local packet capture, excluded from this repository.

Hostnames and addresses below are anonymized examples.

Word at `192.0.2.1` opened `http://sharepoint-server/Shared Documents/Document.docx` from SharePoint at `192.0.2.24`. The capture contains the NTLM handshake and one successful `POST /_vti_bin/cellstorage.svc/CellStorageService` response.

The SharePoint response advertises FSSHTTPB version `13/11`. Extracted Cell payloads:

| Token | Meaning | Bytes | Office Inspectors result |
| --- | --- | ---: | --- |
| 8 | EditorsTable partition | 1,342 | Fully consumed; RevisionManifest, ObjectGroup, StorageManifest, CellManifest, ObjectGroup, StorageIndex |
| 7 | Metadata partition | 364 | Fully consumed; StorageIndex |
| 6 | FileContents/default partition | 151 | Fully consumed; StorageIndex |
| 13 | QueryAccess | 140 | One subresponse |

The repository's current response inspector stops while reading tokens 6, 7, and 8 because it assumes the newer data-element framing. Conversely, the linked Office Inspectors parser consumes all three SharePoint payloads but stops at byte 19 on responses currently generated by OfficeCollabServer.

This is direct evidence that the current server wire framing does not match the successful SharePoint response used by this Word client. The immediate compatibility target should be SharePoint's `13/11` framing and element layout. Keep newer encoding behind an explicit version profile rather than using it for this client.

The SOAP dependency behavior matches the server: Coauth succeeds, and the fallback SchemaLock returns `DependentOnlyOnNotSupportedRequestGetSupported`.
